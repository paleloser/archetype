The `webapp` archetype: a [Next.js](https://nextjs.org/) 16 app (App Router, TypeScript) built with
[HeroUI](https://heroui.com/) v3 and Tailwind 4, authenticated with Auth0, bilingual (Spanish and English), and backed by
the `server` REST API through a generated client.

## Getting Started

This project pins an exact Node/npm version in `.nvmrc`/`package.json#engines` so that local installs produce the same
`package-lock.json` as CI and the production Docker build. Switch to it first (`nvm use`, `fnm use`, or
`volta install node@$(cat .nvmrc)`); npm refuses to run (`engine-strict`) if your Node/npm don't match.

```bash
npm install
```

The `postinstall` script generates the API client into `autogenerated/` with `openapi-generator-cli`, from
`../server/backend/src/main/resources/api/v1.yml`. Re-run `npm install` whenever that file changes.

Copy `.env.example` to `.env.local` and fill in the Auth0 application's values and the API endpoint. Then run the
server (see its README) and the development server, and open [http://localhost:3000](http://localhost:3000):

```bash
npm run dev
```

## Validation

There is no unit test runner: `npm run lint && npm run build` is the validation bar (it is what the `verify-webapp`
workflow runs). Code style is enforced by ESLint, not Prettier: single quotes, no semicolons, 2-space indent, spaced JSX
curly braces (`{ value }`).

## Layout

* `app/(public)`: pages that don't need a session (the error page). Add each one to the `matcher` exclusions in
  `proxy.ts`, which otherwise requires a session for every route.
* `app/(authenticated)`: everything behind the login. The sample is the notes page (`page.tsx`) and the profile page,
  with language and theme switchers.
* `app/<route>/_components`: components used by that route only, re-exported from the folder's `index.ts`.
* `components`: components shared across routes. A component with subcomponents or its own dictionary is a folder
  with an `index.tsx` and an `i18n.ts`.
* `clients/backend.ts`: one factory per generated API. Server components pass the session's token; client components
  pass nothing and the token is fetched per request.
* `lib/i18n`: locale resolution and dictionaries (see below). `lib/auth0.ts`: the Auth0 client. `lib/feedback.tsx`:
  toasts, the single way to report the outcome of an action.
* `proxy.ts`: Next.js middleware: Auth0 routes, the session check, and the login screen's language.

## Internationalization

* Locales live in `lib/i18n/config.ts`. The first one (`es`) is the source language.
* The locale is resolved per request: the `NEXT_LOCALE` cookie (set by the language switcher) wins, otherwise the
  browser's `Accept-Language`, otherwise the default. URLs are not localized: it's an app, not a site.
* Every string lives in a dictionary colocated with its component: `Foo.i18n.ts` next to `Foo.tsx`, or `i18n.ts` next
  to an `index.tsx` or a `page.tsx`. Non-source locales are typed `typeof es`, so a missing key fails the build.
* Server components read them with `await getDictionary(dictionary)`, client components with
  `useDictionary(dictionary)`.

## Theming

Brand colors are CSS variables in `app/globals.css`, which HeroUI reads. Light and dark themes are handled by
`next-themes` (`class` strategy), defaulting to the system preference.
