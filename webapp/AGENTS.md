# webapp conventions

See the [README](./README.md) for the layout. The rules that change how you write code here:

- **HeroUI v3 first.** Build UI from `@heroui/react` compound components (`Select.Trigger`, `Card.Header`...) and
  `@gravity-ui/icons`, styled with Tailwind utilities. Don't add another component library, and check HeroUI's docs
  before hand-rolling a control it already has.
- **Every user-facing string goes through a dictionary.** Never hardcode copy in a component. Colocate it: `Foo.i18n.ts`
  next to `Foo.tsx`, or `i18n.ts` next to a folder component's `index.tsx` or a route's `page.tsx`. `es` is the source
  object, and every other locale is typed `typeof es`, so a missing key is a type error. Read it with
  `getDictionary` (server components) or `useDictionary` (client components).
- **Where components go.** Used by one route: `app/<route>/_components/`, re-exported from its `index.ts`. Used by
  several routes: `components/`. A component with its own subcomponents or dictionary becomes a folder with
  `index.tsx`.
- **Server components fetch, client components interact.** Pages are async server components that fetch with
  `clients/backend.ts` and the session's token, and map failures to a dictionary error key. Client components (`'use
  client'`) call the same clients without a token (it is fetched per request), and report outcomes with
  `useFeedback()` toasts.
- **The API client is generated.** `npm install` regenerates `autogenerated/` from
  `../server/backend/src/main/resources/api/v1.yml`. Never edit it, and re-run `npm install` after the spec changes.
- **Style is ESLint's, not Prettier's:** single quotes, no semicolons, 2-space indent, spaced JSX curly braces
  (`{ value }`). `npm run lint && npm run build` is the validation bar; there are no unit tests.
