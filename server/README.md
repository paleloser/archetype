The `server` archetype: a Java 21 / [Spring Boot](https://spring.io/) 4 REST API, contract-first, in a strict layered
(hexagonal) architecture, with Checkstyle and Spotbugs failing the build.

It ships one sample resource, `Note`, implemented through every layer so there is a working example of each convention.
Replace it with your first aggregate (see [Replacing the sample](#replacing-the-sample)).

# Getting Started

The lifecycle of this project is driven by [Maven](https://maven.apache.org/). We suggest managing Maven and Java
installations with [SdkMan](https://sdkman.io/).

```sh
# Builds the server and starts it locally: in-memory storage, authentication off, no credentials needed.
mvn compile spring-boot:run

curl -s localhost:8080/v1/notes
```

```sh
mvn verify                    # full build: compile, Checkstyle, Spotbugs, unit + integration tests
mvn verify -DskipITs          # skip integration tests (they need Docker, for Testcontainers)
mvn verify -DskipTests        # compile everything, run nothing
mvn compile                   # fast check — Checkstyle already fails the build here, before tests run
```

# Directory Layout

* `pom.xml`: parent POM. Plugin versions and the Checkstyle/Spotbugs/Surefire/Failsafe setup live here, in
  `pluginManagement`, so every module shares them.
* `src/main/config`: _external_ configuration: the Checkstyle ruleset (Google style, 140 columns) and its suppressions,
  the Spotbugs exclusions, and IntelliJ/Eclipse formatter profiles matching Checkstyle. Import the formatter into your
  IDE before writing code.
* `backend`: the application module.
  * `openapi-templates`: overrides for the OpenAPI generator's templates.
  * `src/main/java/com/acme/server`
    * `api`: the REST façade. `api/v1/delegate` implements the interfaces generated from `v1.yml`, `api/v1/mapper` maps
      DTOs from/to the domain, `api/v1/configuration` holds security, CORS, request logging and the global
      `ErrorHandler` (RFC 9457 problems).
    * `boot`: the Spring Boot entrypoint, and `boot/configuration/*Configuration.java`, which instantiate the domain
      services with plain `@Bean` methods.
    * `domain`: the business logic. Nothing vendor-locking here: no Spring, JPA or Jackson.
      * `model/entity`: entities and aggregates, where the business rules live.
      * `model/vo`: value objects (records).
      * `model/exception`: checked exceptions. Their base class (`NotFoundException`, `ForbiddenException`...) decides
        the HTTP status.
      * `repository`, `client`: ports (interfaces) that `infra` implements.
      * `service`: use cases, orchestrating repositories and entities.
    * `infra`: the adapters implementing the domain ports. One package per technology (`postgresql`, `inmemory`...),
      each selected by configuration with `@ConditionalOnProperty`.
  * `src/main/resources`
    * `api/v1.yml`: the OpenAPI contract. Controllers and DTOs are generated from it at `generate-sources`, and the
      webapp generates its client from the same file.
    * `db/migration`: Flyway migrations, `V<NNN>__<Description>.sql`. Never edit one that has been released.
    * `application*.yml`: configuration, per profile.
  * `src/test`: tests mirroring the production packages, plus their Object Mothers and resources.

# Layering Rules

```
api  ──▶  domain  ◀──  infra
            ▲
           boot (wires domain services with @Bean)
```

* **`domain` stays framework-free.** No `org.springframework`, `jakarta.persistence` or `com.fasterxml.jackson` imports
  under `com.acme.server.domain`. `lombok` and `jakarta.annotation.Nullable` are fine.
* **Wiring lives in `boot/configuration`**, with manual `@Bean` methods. Domain classes carry no Spring annotations.
* **Adapters are swapped by configuration, not by editing `boot`.** A new storage, email provider or external API is
  a new package under `infra/` whose beans carry `@ConditionalOnProperty(name = "acme.<port>", havingValue = "<adapter>")`.
  Always keep an in-memory adapter, so the server runs and tests without external services.
* **Mappers are per layer.** `api/v1/mapper/NoteMapper` (DTO ⇄ domain) and `infra/postgresql/mapper/NoteMapper`
  (JPA entity ⇄ domain) share a name on purpose; check the import resolved to the one for the layer you're in.
* **Identifiers are generated by the domain** (`Entity.generateId()`), never by the database.
* **Time comes from the injected `Clock`**, never from a bare `now()`, so tests can pin it.
* **Errors are domain exceptions**, mapped to HTTP only in `ErrorHandler`.

# Code Style and Static Analysis

* **Checkstyle** (`src/main/config/checkstyle-java-google-style.xml`) runs at `process-sources` and **fails the
  build**: 2-space indent, 140 columns, imports in a single ASCII-sorted block (statics first), Google style otherwise.
  A non-conforming file fails `mvn compile`, not just `mvn verify`.
* **Spotbugs + FindSecBugs** run at `prepare-package` (tests included) and fail the build on any finding. Every
  exclusion in `spotbugs-exclude-filters.xml` needs a comment saying why, scoped as narrowly as possible.
* Lombok is welcome for boilerplate (`@Getter`, `@RequiredArgsConstructor`, `@Slf4j`, `@Builder` in Mothers).
* Logs carry context as `[key=value, ...]` at the end: `log.info("Note created [noteId={}]", id)`.

# Testing Conventions

* `*Test` classes are unit tests (Surefire); `*IT` classes are integration tests (Failsafe).
* Test names say what happens, with `@DisplayName("...")`, and bodies follow `// Given`, `// When`, `// Then`.
* Test data comes from **Object Mothers**: one `FooMother` per entity, in the same package as the entity under
  `src/test/java`, exposing `newFoo()` with sensible defaults and a Lombok builder to override one field at a time.
* Domain services are unit-tested with Mockito mocks of their ports.
* Each PostgreSQL adapter has an `*IT` extending `AbstractPostgreSQLIT` (a real PostgreSQL via Testcontainers, migrated
  by Flyway). Register every new DAO and repository in its `@SpringBootTest(classes = ...)`.
* The REST façade is tested end to end with MockMvc against the in-memory adapters (`NotesApiIT`).
* `ApplicationIT` checks that the whole context loads.

# Configuration and Credentials

No credential is stored in `application.yml` — this file is committed, so anything written in it is public forever.
Every secret is read from the environment and defaults to empty, so `mvn spring-boot:run` and the test suite work
without any of them.

| Variable                   | Used for                                       |
|----------------------------|------------------------------------------------|
| `ACME_DATASOURCE_URL`      | JDBC URL of the PostgreSQL database            |
| `ACME_DATASOURCE_USERNAME` | PostgreSQL user                                |
| `ACME_DATASOURCE_PASSWORD` | PostgreSQL password                            |
| `ACME_AUTH_ISSUER_URI`     | OpenID Connect issuer whose JWTs are accepted  |

Integrations should fail lazily, on first use, so missing credentials only matter for the feature that needs them. If
an integration must validate at startup, give it an `acme.<integration>.enabled` switch and document it here.

Profiles: `local` (the default for `mvn spring-boot:run`: in-memory, no authentication), `postgresql` (the local
database from `docker-compose.yml`), `production` (set by the Docker image), `test` (set by the test suite).

# Enabling PostgreSQL Storage

```sh
docker compose up -d   # PostgreSQL at localhost:5435, database/user acme, password pass
mvn spring-boot:run -Dspring-boot.run.profiles=local,postgresql
```

Flyway applies the migrations under `src/main/resources/db/migration` on startup.

# Enabling Authentication

The API is an OAuth2 resource server: it accepts JWT bearer access tokens from any OpenID Connect provider (Auth0,
Cognito, Keycloak...). The token's `sub` claim is the user identity, read in delegates with
`SessionIdExtractor.extractIdpId()`.

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://<your tenant>/
acme:
  authentication:
    enabled: true
```

`/actuator/health` stays public for container health checks, and only reports UP/DOWN.

# Replacing the sample

The `Note` resource touches every layer. To add your own aggregate, mirror these files (and delete them once you no
longer need the example):

1. `api/v1.yml`: paths and schemas. Run `mvn compile` to regenerate the API interfaces.
2. `domain`: entity, value objects, `*NotFoundException`, repository port, service.
3. `boot/configuration/<Aggregate>ServiceConfiguration.java`.
4. `infra/inmemory/repository/<Aggregate>RepositoryInMemory.java`.
5. `infra/postgresql`: `model/entity/<Aggregate>Entity`, `dao/<Aggregate>EntityDAO`, `mapper/<Aggregate>Mapper`,
   `repository/<Aggregate>RepositoryPostgreSQL`, and a Flyway migration.
6. `api/v1/delegate/<Tag>ApiDelegateImpl.java` and `api/v1/mapper/<Aggregate>Mapper.java`.
7. Tests: a Mother, entity and service unit tests, a PostgreSQL `*IT`, an API `*IT`.
